# WayStroke 产品需求与设计决策

WayStroke 面向 Linux Wayland 桌面，通过鼠标手势执行动作，并根据窗口上下文改变行为。已完成核心接入验证，进入正式工程准备；架构与实现阶段见 [实现方案](implementation-plan.md)。本文描述产品目标，不代表功能已经实现；HTML 仍是页面复刻与后续反馈的依据。

## 已确认的产品需求

- 只支持 GNOME 的 Wayland 会话，不适配其他桌面或 X11 会话。开发与验证仅针对用户当前 GNOME Shell / Mutter 50.5（Fedora 44）；不增加跨版本适配。GNOME 会话内 XWayland 的代表性窗口/文本接入已验证，不保证所有应用均提供相同能力。
- 支持通过手势执行快捷键、运行命令、打开程序。
- 支持窗口管理，具体操作与参数见动作目录。
- 手势轨迹采用用户自由绘制的连续轨迹，通过形状相似度识别。支持任意角度、曲线与转折，不量化或吸附到八个方向。此决定替代此前的八方向方案。
- 可以根据不同窗口决定同一手势的行为。窗口专属规则覆盖全局默认行为。
- 目标窗口是手势开始时的坐标对应的窗口，不能用聚焦窗口替代；已取得隔离接口与真实鼠标跨窗绑定证据，正式主桌面时序和复杂窗口场景在集成阶段核对。
- 支持无需编写代码的声明式动作编排：顺序执行、等待、条件分支、有限次数重复、变量。具体操作参考 StrokesPlus.net，并结合实际场景细化。
- 声明式编排需要丰富的可配置动作，以满足充分自定义；不能只提供少量快捷键或预设动作。当前动作范围见 [声明式动作目录](action-catalog.md)，新增能力的技术可行性需分别验证。
- 以按住鼠标右键绘制手势为主要交互，同时支持辅助按键，例如鼠标侧键和左键。
- 保持右键按下期间，辅助键可在绘制开始、途中或画完轨迹后点击；点击后即使先松开辅助键，该次手势仍保留已使用的辅助键组合，松开右键才完成手势。
- 绘制时，在轨迹下方实时显示当前匹配规则的名称，随轨迹与辅助键变化更新；未达到阈值显示“未匹配”，同级候选分差不足显示“手势相近”，尚未达到最小轨迹长度时不显示标签。标签不接收鼠标事件，保持在当前显示器内；下方空间不足时移到轨迹上方。结束、取消、锁屏或断开时清除标签。实时预览与最终识别使用同一算法、起点窗口和配置快照，预览不执行动作。
- 辅助键只用于轨迹手势，不能独立触发动作；不包含组合点击、按住右键滚轮等无轨迹触发。
- 支持键盘关键词自动替换，即文本扩展。例如输入 abc 后确认，将关键词替换为预设内容 2003。匹配边界和输入法行为待细化。
- 文本替换的触发方式可逐条选择，默认以空格或 Enter 确认，保留立即替换选项。
- 参考 StrokesPlus.net 的使用体验；用户长期使用并认可该软件。参考不等于完整复制其功能或界面。

## 已确认的设计协作方式

- 先共同确定需求和规格，再进行正式产品开发。
- 阶段性确认的决定及时保存在项目文件中，避免上下文压缩造成信息丢失。
- 可以在讨论过程中制作和迭代 HTML 设计稿。
- 最终设计稿需要完善，覆盖完整页面、实际交互和关键状态，作为后续一比一实现页面的依据。
- 浏览器预览呈现带边框的桌面应用窗口，窗口外保留背景，内容在应用窗口内部滚动。
- 提议不得当作已确认决定，待定需求不得自行缩减。
- 常规设计取舍由助手依据现有需求直接决定并说明；仅对需要用户偏好、明显取舍或新增范围的问题征求意见。助手采用的默认值与用户明确确认的需求分开记录。
- 自主决定的设计也必须完整记录，并在 HTML 设计稿的页面、交互、参数、默认值或状态文案中体现，不得因为未逐项询问而省略。
- 设计文件与 HTML 保持同步。仅写入文字、尚未体现在 HTML 的决定明确标为待补，不视为设计稿已完成；最终规格确定前需要补齐。

## 已接受的设计方向

用户接受上一轮推荐，以下作为当前设计基础，具体页面视觉仍需审核。

- 一条规则由触发方式、窗口匹配条件、动作或动作序列组成。
- 应用或窗口专属规则覆盖全局规则，无专属匹配时使用全局默认行为。
- 声明式动作编辑器采用可排序的步骤列表，条件分支嵌套显示。
- 手势规则作为主页面，提供规则编辑器、测试区和设置页面。
- 测试区显示识别结果、匹配规则和将执行的动作；实际执行需主动触发。
- 自由轨迹识别忽略绘制位置和整体大小，保留朝向与绘制顺序，避免相反方向被合并。正式算法仍需验证。

## 当前采用的设计默认值

以下由助手根据既有需求采用，作为下一版设计稿的基础；用户可在讨论中调整，不等同于每项均已单独确认。

### 手势与规则

- 手势形状作为可复用的录制模板；规则将模板、辅助键、窗口范围与动作关联。同一形状跨应用复用时，无需重复录制。
- 每个模板支持一个主要录制样本，以及按需添加的其他样本。新增样本必须主动保存，测试不会自动修改模板。
- 保存录制的真实形状，另行生成用于比较的标准化数据；不将展示轨迹改成标准方向。
- 普通右键点击保持原行为。进入有效手势后，未识别或主动取消均不执行动作，也不弹出右键菜单。最小有效轨迹与取消机制的具体参数待验证。
- 全局启停、应用禁用、窗口规则、全局默认规则按此顺序决定是否处理。应用禁用时原始鼠标操作透传。
- 窗口匹配先筛选作用范围，再比较手势形状。匹配阈值内的候选按应用与标题条件优先级选择：应用且带标题条件、应用通用、全局且带标题条件、全局通用。同级候选存在歧义时不随意执行。

### 窗口上下文

- 按下手势主键时固定起点窗口，手势中途跨窗口不重新绑定目标。
- 无应用窗口的桌面区域只参与全局规则；需要目标窗口的动作不可执行。
- 窗口范围提供应用标识与可选标题条件。应用标识优先从窗口选取，避免用户手工填写；标题采用等于、包含等可读条件。
- 应用名称用于显示，应用标识用于匹配；允许手动填写标识并添加自定义应用。标题条件支持包含、等于和不包含，按大小写精确比较。
- 发送快捷键或输入文本前，激活起点窗口；窗口管理直接作用于起点窗口。激活失败或目标窗口消失时停止当前动作序列并显示原因，不把输入转发到其他窗口。
- 动作序列若主动打开或切换应用，需要显式步骤将后续动作目标改为该窗口，避免目标随桌面焦点隐式变化。

### 声明式动作

- 步骤默认顺序执行，支持上移、下移、复制、删除与嵌套分支。
- 简单动作可在规则侧栏编辑；复杂动作提供同一应用窗口内的全宽编排视图，容纳步骤树、参数与变量，已加入 HTML。
- 基础动作包括快捷键、运行命令、打开程序、窗口操作和输入文本；编排动作包括等待、条件分支、有限次数重复、设置变量，以及显式改变目标窗口。
- 等待支持固定时长或条件成立，例如目标窗口出现；条件等待提供超时参数，超时视为步骤失败。
- 变量基础类型为文本、数字与布尔值，默认仅在当前动作序列内有效。上下文值如起点应用、窗口标题和剪贴板通过值选择器插入，无需编写表达式代码。
- 重复支持固定次数或数字变量，不支持无限循环。
- 步骤失败时默认停止序列并展示失败步骤和原因；需要继续的场景由该步骤显式设置，不静默兜底。
- 测试先预览匹配与步骤；执行实际动作由用户主动触发。
- 全宽视图的编排先应用回规则，再保存规则；可复用动作在管理页面直接保存。取消编排会保留进入前的规则编辑状态。
- 可复用动作使用稳定引用，修改同步影响所有调用，复制生成独立副本。被引用时阻止删除，并列出引用来源；禁止直接或间接递归调用。
- 可复用动作可声明输入参数、默认值及返回字段。调用步骤根据所选动作生成输入表单，并可将返回数据保存到输出变量。
- 支持从规则编排另存为可复用动作，可同时把当前编排改为引用新动作；窗口匹配条件仍属于规则，不随步骤复制到动作中。
- 变量插入通过选择器完成，列出上下文、输入参数及此前启用步骤的输出。分支与循环内部变量不自动泄漏到外层，后续步骤的输出不能提前引用。

### 文本替换

- 默认以空格或 Enter 确认，逐条可选立即替换、只用空格确认或只用 Enter 确认。
- 默认按大小写精确匹配完整关键词；关键词前要求文本起点或非文字字符。立即模式只检查关键词前边界，不能保证后边界。
- 默认保留确认键原有作用，例如替换后保留空格或换行。若需吞掉确认键，规则提供显式选项。
- 保留多行纯文本、应用范围和应用排除；输入法组合过程不触发替换，以提交后的文本为目标，实际获取与替换能力需要验证。
- 同一关键词存在应用专属规则时，覆盖该应用中的全局同关键词规则，包括其触发方式；停用的专属规则不覆盖全局规则。
- 撤销仅用于当前字段里范围仍可确认的最近替换；切换焦点、导航或继续编辑后交还应用原生撤销。终端只撤销紧邻且未提交换行的替换；生成内容与撤销不再次触发规则。
- 技术验证确认：Firefox 和本机 Electron 的普通编辑区域可通过周围文本协议替换；密码字段可识别并阻止替换。XWayland GTK 可用 AT-SPI 编辑/密码角色及 GNOME 确认键协作，当前 Rime 的额外组合保护也已验证；不保证任意应用/输入法均提供这些能力。Ptyxis 的无回显密码提示仍只上报 TERMINAL，不能可靠区别于普通终端输入。用户随后明确允许终端普通输入和密码输入都自动替换，因此终端路径不再以密码识别为前置条件，继续验证通用输入跟踪与编辑按键路径，而不是只支持 Zsh 命令行。不同终端程序的退格、光标和确认行为仍需验证；不把未知能力显示为已支持。此决定针对终端，不自动取消其他应用已设计的密码字段保护。

## 当前页面与操作流程

浅色紫色视觉、桌面窗口边框与窗口内滚动作为当前设计基础。侧栏包含手势规则、手势模板、可复用动作、文本替换、手势测试、运行状态、配置与备份、设置。

- 手势规则：筛选与搜索列表，右侧常驻编辑器；编辑名称、窗口范围、辅助键、自由轨迹及动作。保存或取消，未保存离开时确认。
- 手势模板：模板列表与样本编辑区；录制、重录、添加样本、试画对比；修改共享样本时提示影响的规则。
- 可复用动作：列表、新建、复制、引用来源及删除反馈；编辑进入全宽编排。
- 全宽编排：步骤树、参数、变量与接口三栏；支持嵌套、排序、复制、启停、失败设置、输入与返回字段、变量插入。复杂参数采用键值表、坐标字段和 D-Bus 类型化参数表。
- 文本替换：列表、编辑弹窗及页内试输入；触发方式、应用范围、大小写、关键词边界和确认键保留均可配置。
- 手势测试：自由试画，显示候选、分值、起点窗口、匹配依据及动作摘要。
- 运行状态：桌面接入、独立鼠标/文本功能状态、当前执行/排队与停止、最近执行和失败详情；提供文本适配范围、重新连接、与当前状态一致的诊断摘要及接入向导入口。
- 配置与备份：导出、文件选择、导入摘要、合并或替换、确认弹窗、本地备份恢复与删除。
- 设置：鼠标设备选择、轨迹反馈、识别阈值、取消参数、串行动作策略、自动启动、文本替换及终端路径独立开关、应用排除。终端开关默认开启，普通及密码输入均参与；关闭即停用整个终端路径，不伪称只识别并排除终端密码。初次设置为欢迎、桌面接入、开始使用三步，桌面接入包含扩展、鼠标服务管理员授权和设备选择。

## 设计稿范围（按最新意见调整）

HTML 是确认最终界面和交互的设计稿。完善程度以布局、操作流程和状态覆盖衡量，不以业务引擎的完整度衡量。

保留页面切换、自由绘制、样本编辑、动作树与参数编辑、变量插入、简单页内文本替换和浏览器内保存编辑，以便评审操作体验。保留必填反馈、未保存离开、删除与共享修改确认等低成本交互。

配置导入只显示所选文件名和固定摘要，不读取内容或执行迁移；导出、恢复和导入完成仅显示示例反馈。备份列表是内存中的界面样本。运行状态和步骤结果使用固定场景，不求值分支、不执行重复、不模拟完整执行器，也不根据桌面示例状态阻止页内评审。变量选择保留编辑辅助，不实现完整类型验证或引用重命名传播。

窗口外的“界面评审”工具可切换默认、空状态、错误示例、桌面接入状态及初次设置。此工具不属于正式应用，不在未来一比一复刻范围内；窗口内的页面、控件、弹窗和反馈才是复刻依据。示例不会清除已编辑配置。

入口为 `design/index.html`。动作目录含 10 类、69 个可配置动作，详见 [动作目录](action-catalog.md)。当前设计稿已作为正式复刻基线（见文末补齐记录），用户仍可反馈修改；不能据此声称系统功能已完成或技术可行性已验证。

## 留在正式产品规格中的复杂规则

- 变量类型：文本、数字、布尔值、列表、窗口、结构化数据。输出字段类型由动作定义；输入类型不匹配时定位步骤与参数，禁止执行。分支与循环局部值不泄漏；引用按稳定标识维护，重命名同步更新调用参数及引用，删除被引用值前提示来源。
- 编排：有限重复、条件等待超时、循环退出仅在循环内、禁止递归调用；默认失败即停止，可显式记录失败并继续。用户取消后停止剩余步骤，实际执行结果包含步骤、原因和状态，不伪造成功。
- 配置：带格式标识与版本；验证结构、未知动作、引用完整性及递归。导入与恢复前自动备份，保留最近 5 份。合并保留现有偏好；同关键词与应用的文本替换保留现有条目；标识冲突的动作与手势生成副本并维护引用；触发相同的规则副本默认停用。替换完整采用配置。运行状态、授权与执行记录不迁移；失败不得部分覆盖原配置。
- 桌面状态：扩展缺失、输入访问未就绪、服务中断、不支持的会话均需解释原因与恢复入口；接入不可用时配置仍可编辑。状态来自真实桌面服务，不能由界面假定。
- 文本替换：输入法组合期间不替换；真实提交后按规则处理，撤销与自身生成输入不再触发。其他应用密码字段默认排除；按用户最新决定，终端密码输入允许替换。

这些需求保留在产品范围内，demo 不承担实现或验证它们的职责。

## 识别参数与技术待验证项

评审中的自由轨迹采用按弧长重采样、统一比例缩放后比较，忽略位置与整体大小，保留宽高比例、朝向和顺序。初始阈值 82%，同级前两候选差距不足 5 个百分点提示歧义；分值并非识别成功概率。最小轨迹默认 12 像素、停留取消默认 1200 毫秒，Esc 立即取消。这些数值是设计默认值，正式算法和手感需实际样本验证。

早期开发前验证清单包含 GNOME Shell 版本、全局手势捕获、起点窗口命中、输入注入、IME 提交文本、剪贴板和权限接入，以及 GNOME 会话中 XWayland 应用。当前核心接入验证与技术路线已有结论，见技术验证文档和完整开发计划；剩余剪贴板、截图及系统动作接入纳入正式任务 C04/C05，不把页面默认值重新列为未决定需求。

## 锁屏行为（技术验证补充）

GNOME 锁屏时停止手势捕获与动作执行，取消当前动作序列和文本补全上下文，释放输入设备。锁屏期间不读取或缓存文本；解锁后不重放锁屏前的点击、手势或文字。正式后端订阅锁屏状态变化，界面在恢复后显示正常状态；不能依赖界面进程轮询作为唯一取消机制。

## 实现基线补齐（2026-10-13）

当前 HTML 已补齐技术验证与架构决定对应的页面和文案，作为正式客户区复刻基线。保留规则连续滚动、固定保存栏、动作编排三栏和既有页面结构。新增状态采用固定样本，不扩展成完整运行模拟器。

- 标题栏提供最小化、最大化/还原和关闭设置。关闭设置后后台继续运行，运行状态页的退出操作才停止功能；未保存时关闭或退出须确认放弃，最小化保留草稿。
- 服务连接不等于所有文本输入可替换；适配范围区分普通、XWayland、终端、输入法组合、密码字段和缺少编辑能力的场景。终端以有限兼容的通用路径说明，不能伪称能识别所有原始输入程序的编辑模式。
- 鼠标权限未就绪时，手势等待授权，但已连接的文本接入可继续工作。锁屏时两者暂停，已取消的动作不因解锁而恢复。
- 原型恢复数据、输入/执行场景选择留在窗口外；正式设置不包含设计稿数据管理。窗口内的版本号、设备列表及运行结果目前仍是样本，正式实现绑定实际数据。
- 正式壳层中的 Tauri 窗口控制、WebKitGTK 字体/尺寸和桌面状态还需实际比对；后续用户反馈仍可修改基线，不把设计稿称为已经完成的桌面应用。
